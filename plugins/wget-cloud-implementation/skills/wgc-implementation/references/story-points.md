# Оценка в story points

Оценщик Effort Estimator отделён от Task Assessor (выбор risk/team/test gates). Оценка SP не является разрешением реализовывать и не снижает security/architecture gates.

Шкала: `1, 2, 3, 5, 8, 13`. Сравнивай относительный объём, сложность и неопределённость полного результата: исследование, реализация, тесты, ревью, интеграция и подготовка доставки. Не пересчитывай SP в часы/деньги, не заполняй SP в period fields. Для отсутствующего результата ставь unknown, не 0. Для >13 предложи декомпозицию; для доминирующей неизвестности — ограниченное Research с вопросами и deliverable. Оценка после снятия неизвестности обновляется с объяснением.

## Калибровка

Найди 2–3 завершённые сравнимые задачи команды с принятыми SP и подтверждённым scope. Если их нет, предложи начальные ориентиры (1 — небольшое локальное изменение; 3 — ограниченный сценарий с проверками; 5 — несколько связанных путей; 8 — сложная интеграция; 13 — крупная работа для проверки декомпозиции). Явно пометь шкалу provisional и выясни ожидания команды; не выдавай ориентиры за историческую velocity.

`EffortEstimate`: task code/ID, plan revision, SP или unknown, confidence high/medium/low, comparison anchors, rationale, assumptions, risks, decomposition recommendation, calibration group. Автор плана не утверждает свою оценку; отдельный оценщик исследует основания и сообщает расхождения. После существенного изменения AC/dependencies нужна переоценка.

## Эпики и запись

Каждая задача оценивается отдельно. Родитель с оценёнными подзадачами показывает rollup, а не дополнительную стоимость той же работы. Остаточная работа родителя должна быть выделена отдельно. Суммируй только непересекающиеся work units с одной calibration group; межкомандные итоги показывай раздельно до согласования общей шкалы. Эпик не получает независимую добавочную оценку поверх задач. SP не равны сроку выпуска и не уменьшаются пропорционально «проценту готовности».

Через MCP прочитай текущую schema каждого проекта. Повторная проверка через MCP 14.09.2026 подтвердила `Story Points` типа `integer` во всех семи проектах: PRD, BE, FE, SITE, WGET, FL, K8S. Записывай оценку в это поле через `customFields`, например `{"Story Points": 5}`, затем перечитай карточку. Обоснование и confidence сохраняй в описании. Это snapshot, не вечная настройка: перед записью всегда проверяй актуальную schema. Для enum используй только подтверждённое соответствие значения schema. Если поля нет — сохрани SP/основания в описании и сообщи об отсутствующем поле. Создание административного поля требует отдельного scope и доступного административного MCP; не обходи отсутствие инструмента REST/curl. Часовые поля не меняй.
