# Проверки без дублирования

Один назначенный владелец выполняет проверку; остальные используют актуальный результат, оценивая его достаточность. Reviewer проверяет смысл assertions и diff, QA — поведение; никто не повторяет всю suite коллеги автоматически.

Повтор требуется после релевантного изменения, failed run, изменения окружения/зависимости или нового риска. Факт запуска до изменения не доказывает текущее состояние. При неясной области влияния проверка повторяется. Проверки AGENTS.md/CI обязательны; шаблонный список плагина — подсказка для поиска настоящих требований, не дополнительный universal CI floor.

Hooks хранят только метаданные: hash/id команды, revision, environment fingerprint, scoped paths, owner и successful flag. Окружение здесь означает контекст запуска; реальную версию сервиса/данных/зависимостей проверяет владелец evidence. Raw commands/output не сохраняются. Ошибка повторной проверки отменяет прежний успех. Source/lock/config change отменяет относящиеся к нему результаты; при неизвестной зависимости не переиспользуй прошлое evidence.

Новый тест нужен для конкретного изменяемого invariant или воспроизводимого дефекта. Порядок рассмотрения: existing relevant test → update → add; none при обоснованном отсутствии regression value. Не создавать mirror-тесты, формальные assertions и необоснованные snapshots. Не менять coverage thresholds ради экономии. Не вводить отдельного постоянного Test Auditor или Token Auditor.

Отчёт короткий: результат, changed scope, проверки и evidence, blockers. Не пересказывать историю задания. Передача finding: scenario → evidence → impact → required behavior. Не объявлять отсутствие дефектов гарантией безошибочности. Token usage измерять только из доступной фактической телеметрии; размер контекста и число запусков — отдельные proxy, не выдуманные токены.
